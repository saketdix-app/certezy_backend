# S3 setup for Certezy uploads

Admin uploads (course thumbnails, preview videos, lesson videos, category icons)
go **directly from the browser to S3** using a pre-signed URL from
`POST /api/v1/upload/presigned-url`. The API also writes certificate and invoice PDFs
to the same bucket. Files are served from their public S3 (or CloudFront) URL.

```
uploads/images/YYYY/MM/<uuid>-name.png    ← admin uploads
uploads/videos/YYYY/MM/<uuid>-name.mp4
uploads/documents/YYYY/MM/<uuid>-name.pdf
certificates/CERT-....pdf                 ← generated by the API
invoices/INV-....pdf
```

## 1. Create the bucket

S3 → Create bucket, e.g. `certezy-uploads`, in the same region as the EC2 server.

- **Object Ownership:** ACLs disabled (the default). Leave `S3_USE_ACL` unset.
- **Block Public Access:** untick only the two *"…public bucket policies"* boxes
  (needed for step 2). Keep the two ACL-related boxes ticked.

## 2. Bucket policy: make uploaded files publicly readable

Bucket → Permissions → Bucket policy (replace `certezy-uploads` with your bucket name):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadForSiteAssets",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": [
        "arn:aws:s3:::certezy-uploads/uploads/*",
        "arn:aws:s3:::certezy-uploads/certificates/*",
        "arn:aws:s3:::certezy-uploads/invoices/*"
      ]
    }
  ]
}
```

> Invoices contain customer names and emails. Drop the `invoices/*` line to keep them
> private; links to invoice PDFs will then return 403.

## 3. CORS: allow the browser to upload

Bucket → Permissions → CORS. List every address the site is opened from:

```json
[
  {
    "AllowedOrigins": ["http://54.237.250.101", "https://certezy.com", "https://www.certezy.com"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

Without this, uploads fail in the browser with
*"Could not reach S3 — check the bucket CORS settings"*.

## 4. Credentials: IAM role on EC2 (recommended)

IAM → Roles → Create role → AWS service → EC2, then add this inline policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::certezy-uploads/*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::certezy-uploads"
    }
  ]
}
```

EC2 → your instance → Actions → Security → Modify IAM role → select the role.
Then leave `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` **empty** in `.env`.

Alternative: create an IAM user with the same policy and put its access keys in `.env`.

## 5. Backend `.env`

```
AWS_REGION=us-east-1
AWS_BUCKET_NAME=certezy-uploads
# optional: serve through CloudFront or a custom domain
# S3_PUBLIC_URL=https://cdn.certezy.com
```

Restart with `pm2 restart backend --update-env`.

## 6. Verify

While signed in as admin, open `http://<server>/api/v1/upload/status` in the browser.
`"ok": true` means the API can reach the bucket.

Then upload a thumbnail in Admin → Courses → Create/Edit Course.

## Optional: CloudFront

Create a CloudFront distribution with the bucket as origin (Origin Access Control)
and set `S3_PUBLIC_URL=https://<distribution>.cloudfront.net`. You can then remove the
public bucket policy from step 2 and grant CloudFront read access instead. Files
uploaded before the switch keep their old S3 URLs.
